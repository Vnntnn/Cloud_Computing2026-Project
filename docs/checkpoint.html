The constraint that shapes everything

A $50 hard cap and 4-hour credentials.

budget $50, hard-capped. Exceed it and the account locks and wipes.

≈ $0.27/hr up, $3.40/day idle. Left running, $50 is gone in 15 days — before the demo.

What is deployed

Three services, one SPA, one database instance.

auth better-auth · Drizzle · JWT + bearer plugins · email/password + Google OAuth · owns auth_db · publishes /api/auth/jwks
event event metadata · S3 presigned cover images · verifies callers' JWTs locally against JWKS · owns event_db
registration owns & enforces capacity by counting its own rows in one local transaction · owns registration_db
web React SPA on nginx inside the cluster — one origin, no CORS, no CloudFront

Elysia + Bun, compiled to a single binary on distroless — 44 MB per service image.

Request path

One NLB, one ingress, four services.

Probed live against the account

The lab denies things. Each denial forced a decision.

  • iam:GetRole on voclabs rules out terraform-aws-modules/eks → raw aws_eks_cluster + native creator-admin bootstrap
  • iam:CreateRole reuse the lab's pre-made LabEksClusterRole / LabEksNodeRole, looked up by regex
  • CreateOpenIDConnectProvider no IRSA, and no GitHub-Actions OIDC → CI builds the image, deploy is a local script
  • iam:AttachRolePolicy pods can't get node credentials either → the app is built to need no AWS SDK, ever
  • SCP: GetBucketObjectLockConfiguration every S3 bucket is CLI-created, consumed as data "aws_s3_bucket"
  • cloudfront:* the SPA is served from inside the cluster instead; TLS will be Cloudflare-proxied

The decisions worth defending

Constraints that improved the design.

boundary, not saga Capacity lives with the ticket rows, so booking is one local transaction — the service split was placed to avoid a distributed transaction.
engine-enforced isolation One instance, one database per service. PostgreSQL cannot join across databases — the boundary is not a convention.
asymmetric JWT event / registration hold only a public key. They verify locally against JWKS and are cryptographically unable to mint a token.
bearer, not cookies Identical in dev and deployed — no two SameSite configs. The localStorage / XSS exposure is stated, not hidden.
